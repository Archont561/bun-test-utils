`bun-test-utils` extends [`bun test`](https://bun.sh/docs/test/overview) with a
typed fixture model: a fixture is a value built by a `setup` function, tests ask
for the fixtures they need by destructuring, and the engine builds dependencies
first and tears everything down in reverse order, even when a test fails.

It is **not** a replacement for `bun:test` — it ships no runner of its own, and
your tests stay `bun test` files. It is not a browser-only framework either:
fixtures, standard fixtures, HTTP mocking, and cassettes work in any Bun project,
and the DOM, browser, property-based, and BDD layers install with their own
optional peers when you reach for them.

## Add-on capabilities

Each one installs its own optional peer and is requested like any other
fixture; nothing is pulled in until a test asks for it.

| Capability | Use it for | Maturity | Requires |
| :-- | :-- | :-- | :-- |
| [DOM testing](/bun-test-utils/capabilities/dom-and-browser/) | Component and markup assertions in-process, without a browser | Stable | `happy-dom` |
| [Browser testing](/bun-test-utils/capabilities/dom-and-browser/) | Real layout, focus, and input in headless Chromium | Experimental | `playwright` + Chromium |
| [Snapshot testing](/bun-test-utils/capabilities/snapshots/) | Reviewed baselines for values, files, and callback results | Stable | — |
| [Property-based testing](/bun-test-utils/capabilities/property-based-testing/) | Generated inputs that shrink to a counterexample | Stable | `fast-check` |
| [BDD scenarios](/bun-test-utils/capabilities/scenarios/) | Fluent `given` / `when` / `then` chains on the same fixtures | Experimental | `@aboviq/bun-test-cucumber` |
| [HTTP cassettes](/bun-test-utils/capabilities/cassettes/) | Recorded request/response pairs that replay deterministically | Stable | — |

The [capability index](/bun-test-utils/capabilities/) has the full decision
table, the parameterized-test alternative to property tests, and links into
every guide.

## Quick start

Install the package and wire its preload once per project:

```bash runnable
bun add -d @archont561/bun-test-utils
bunx test-utils init --yes
```

`init` adds the package's preload to `bunfig.toml`; it installs run-wide
teardown hooks and loads no fixtures of its own. Built-in fixtures are then
available to any test that requests them:

```ts title="greeting.test.ts" runnable
import { expect, test } from "@archont561/bun-test-utils";

test("greets through a built-in fixture", async ({ tmpdir }) => {
  tmpdir.write("greeting.txt", "hello");
  expect(tmpdir.read("greeting.txt")).toBe("hello");
});
```

```bash runnable
bun test
```

Expected output:

```text
 1 pass
 0 fail
 1 expect() calls
```

[Install and first passing test](/bun-test-utils/start/first-test/) shows the
same flow with a fixture of your own, complete `tsconfig` output, and the
failure modes.
